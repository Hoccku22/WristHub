# Bluetooth-транспорт

Решение: защищённый Bluetooth Classic RFCOMM. Часы открывают
`listenUsingRfcommWithServiceRecord("WristReader", UUID)`, телефон вызывает
`createRfcommSocketToServiceRecord(UUID).connect()`. UUID приложения:
`1826c0e3-39dc-483b-a833-70dccd7ecf21`.

В исходниках нет Data Layer, ChannelClient, сетевых сокетов, BLE GATT или HTTP-клиента.
В итоговых манифестах не должно быть INTERNET, ACCESS_WIFI_STATE или CHANGE_WIFI_STATE.
Сам BluetoothSocket RFCOMM не умеет переключаться на Wi-Fi. Это свойство выбранного
транспорта; доступность сервиса и успешная передача на конкретной прошивке проверяются отдельно.

## Разрешения и сопряжение

Android 12+: только runtime BLUETOOTH_CONNECT для обмена с уже сопряжёнными устройствами.
Android 8–11: BLUETOOTH с maxSdkVersion=30. Сканирование приложением не выполняется,
поэтому BLUETOOTH_SCAN, BLUETOOTH_ADMIN и геолокация не нужны.
Сопряжение выполняется системными средствами / приложением-компаньоном Xiaomi.
Телефон показывает список bondedDevices. Имя и адрес нужны для выбора именно часов.

Начиная с 1.2 приём автоматически включается при открытии приложения на часах
после выдачи разрешения Bluetooth. Принимаются только bonded-устройства.
Канал защищён стандартным системным сопряжением Bluetooth; отдельного пароля приложения нет.
Во время приёма любое уже сопряжённое устройство с этим протоколом может отправить файл.
При сворачивании приложения сервер и активный сокет закрываются. Можно также
отключить приём кнопкой. Bluetooth-сопряжение и системное подключение телефона
при этом не разрываются. Сворачивание во время передачи отменяет незавершённый пакет.

Обе стороны используют foreground service типа connectedDevice, уведомление с остановкой
и частичную wake lock только на время обмена. Служба не перезапускается автоматически
после принудительной остановки или перезагрузки. Отказ в уведомлениях не отменяет
возможность foreground service, но видимость уведомлений зависит от версии Android.

## Формат WR01

Java DataOutputStream, big-endian:

1. int `0x57523031`, writeUTF UUID, writeUTF отображаемое имя, writeUTF MIME.
2. long размер оригинала, long размер UTF-8 текста.
3. 32 байта SHA-256 оригинала, 32 байта SHA-256 текста (включая пустой).
4. Ответ: int READY=1, COMMITTED=2 или REJECTED=3, затем writeUTF пояснение.
5. После READY: ровно size байт оригинала и textSize байт текста.
6. Часы проверяют оба хеша, синхронизируют содержимое файлов, записывают метаданные
   и переименовывают временную папку в завершённую в той же файловой системе.
7. Только затем отправляют COMMITTED. Повтор того же UUID и хешей идемпотентен:
   уже полученный документ повторно не копируется. Это покрывает потерю финального ACK.

Имена пользователя никогда не используются как пути. Пределы: оригинал 512 МиБ,
текст 32 МиБ, запас свободной памяти 8 МиБ. Оригинал и текст образуют одну транзакцию.
Буфер копирования — 32 КиБ. Частичные папки скрыты от библиотеки, удаляются при
ошибке и при следующем включении приёма после аварийного завершения процесса.

Отмена закрывает сокет, пробуждая заблокированное чтение/запись. Повтор начинается
с начала файла. Сетевого резерва нет. Подключение ограничено 30 секундами,
отсутствие активности при обмене — примерно 90–95 секундами. Активная wake lock
ограничена одним часом; время передачи 20 МиБ зависит от радиоусловий.

## Основания и ограничения

- [Android: соединение Bluetooth RFCOMM](https://developer.android.com/develop/connectivity/bluetooth/connect-bluetooth-devices).
- [Android: разрешения Bluetooth](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions).
- [Wear OS: rotary input Compose](https://developer.android.com/training/wearables/compose/rotary-input).
- [AGP 8.9: совместимость Gradle 8.11.1 / JDK 17 / SDK 35](https://developer.android.com/build/releases/agp-8-9-0-release-notes).
- [PDFBox Android](https://github.com/TomRoush/PdfBox-Android).

Общие Android API не являются обещанием производителя о работе профиля на любой
прошивке часов. При ошибке SDP / отказе сокета приложение сообщает об ошибке и
останавливает отправку. Если OEM блокирует RFCOMM, менять транспорт на Data Layer
нельзя: нужна проверенная поддержка прошивки или новая Bluetooth-only реализация.

ADB по Wi-Fi может использоваться для установки и диагностики; он не является
транспортом файлов WristReader. Проверка обмена выполняется отдельно с Wi-Fi,
мобильными данными и ADB, отключёнными на обоих устройствах.
